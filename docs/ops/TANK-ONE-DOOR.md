## The intended ladder and what changed

For each client and task type: try deterministic code, a correctly scoped saved answer, our search and browser, then the cheapest funded paid option when the free work cannot answer. Tank chooses policy, enforces scope and spending, and records every paid attempt. Agents must not hold inference credentials or submit paid jobs themselves.

Base now enters `run_code_first` (`agents/base/room.py:459`, `base_brain.py:38`). It runs the existing pipeline with `_base_brain_free`, which already removes model and paid-key capability from the skill context in Tank (`tank/agent_skills.py:504`). If the completed batch has no unresolved records, no brain starts. Otherwise recovery receives the completed free result; repeated pipeline callbacks reuse it. The existing single paid continuation, cancellation, tenant checks and receipts remain in place. A paused or failed prepass is not permission to spend. Direct `drive_batch` remains a compatibility entry point; the queue uses `run_code_first`.

Autumbra's optional synthetic dogfood now uses the existing Ghost Tank client, `/v1/route`, `reason.brief`, and the platform tenant (`agents/ghost/dogfood_hf.py:61`). It preserves the 200-token output cap, requires a valid ledger ID, rejects model overrides and never reads an HF token. Existing explicit live gates and historical CLI/receipt field names remain compatible. No live paid request was made.

No production secrets or browser artifacts were inspected; source review cannot certify a deployed bundle. Several server modules rely on convention rather than `import 'server-only'`; the security thread can enforce that boundary.

`tests/test_tank_one_door.py` scans tracked **and untracked** Python/JS/TS/HTML/shell/config source outside `tank/`.
