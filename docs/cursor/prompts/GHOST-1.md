Repo Tervory-AI/tervory-tank. Read AGENTS.md, docs/cursor/CONTEXT.md and docs/cursor/ROOMS.md, then docs/cursor/GHOST-1-onsite-agent.md and do all of it.

Ghost is a new squad member at agents/ghost/: the permanent onsite agent that only solves problems it is pointed at. Its own room in the ROOMS.md shape, with its own memory, browser and bucket (tervory-ghost). It watches uptime and response time of the sites and every room, error patterns in the Workspace and Tank logs (never secret values), certificates and DNS, failed deploys and red CI on main, and security headers. An issue reaches it by its own alert, the founder pressing Look, or a message. It reproduces the problem, finds the cause, writes the fix as a worker brief (never a direct change), or does only the safe actions it is allowed: re-run a failed deploy, restart a crashed room. Read-only on production data; never changes keys, settings or the database; never merges; anything else needs the founder's OK. Ghost is not Radix: it never scans code itself, it hands code to Radix through Tank, and Radix stays sealed. Solved issues go to its memory and become gold (ghost:incident:{YYYY-MM}). Every investigation has a receipt through Tank.

Five other lanes are running at the same time. In tank/main.py and tank/schema.sql add only route registrations and additive schema, so merges stay clean. Branch from latest main. Stay inside the brief's "Files you may change". No secrets in code, URLs, logs or tests. One branch, one PR, never push to main. Do not merge: the founder merges after review. Open a draft PR early so CI runs; mark it ready and write "ready for review" only when every check is green. End the PR with how to prove it live after deploy: which page, route or database row to check.
