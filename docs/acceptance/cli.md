# CLI founder acceptance sheet

Scope: CLI 0.1.0–0.6.0 (all waves through 3 Nov 2026). Each numbered row has one
collected pytest case in `tests/acceptance/test_cli.py`; the last column names its
executable behavioral fixture. Fixtures call the real CLI, local tool, Workspace
adapter/component or signature implementation, with synthetic transports/data.
They assert values and side effects, not source-code strings. Existing Node
fixtures are reused; pytest refuses missing, failed or skipped proofs. No real
model, provider, account, production SQL or founder computer is used offline.

## Before founder testing

- Deploy the reviewed release and use Node 22, Git and an unlocked OS keychain.
  Linux/macOS command tests additionally require their supported sandbox. Windows
  commands run after explicit approval with host user permissions; native archive/launcher checks also run in
  `cli.yml` on Windows. A Linux offline proof exercises the shared tool interface
  with Bubblewrap; it does not claim to execute the native macOS backend.
- Use your own test organization/device. For action/plugin/MCP rows, enable the
  corresponding squad, use a tenant administrator for installs/removals, and
  connect the already approved official GitHub MCP server through existing
  product connections. Do not grant another tenant access or use real secrets.
- Create an expendable Git folder `acceptance-repo` with `file.txt`, `second.txt`
  and `third.txt`, each containing `old` plus a newline; make a child directory.
  Create `outside.txt` beside it containing a dummy canary. Other row-specific
  files are scratch data only. Do not alter system sandbox executables to test a
  refusal; use the fixture for unavailable-platform cases.
- Angle brackets are actual values printed/generated at runtime, not text to
  paste. Copy the real thread id/code/model/version where shown. Fixture IDs,
  prices, answers and dates are explicitly labeled; live model prose and costs
  are not fixed. Compare live receipts byte-for-byte with that same thread's
  receipt in `/chats`, rather than expecting a fixture price or model answer.
- Trigger sign-in is the only browser and CLI sign-in in both regions. Native
  device approval uses auth.tervory.com in the US and auth-za.tervory.com in ZA;
  the Workspace device approval page is removed. Setup creates the project and
  apps, publishes generated IDs and links organisations to existing tenants.
  Founder checks use the verified raw subject recorded by setup, never email.
  The Workspace sign-ins list can revoke the caller's regional CLI credentials.
  See `docs/ops/TRIGGER-SIGNIN.md`; `none` below means no additional setting.

Settings source: `docs/ops/FOUNDER-SETTINGS.md` from PR #657, read from
`origin/claude/founder-settings` without merging it. The CLI entries are
`CLI_RELEASE_SIGNING_KEY` and `CLI_RELEASE_SIGNING_PUBLIC_KEY`. Names only.
The shipped signing workflow reads the private key from GitHub Actions secrets
and the public key from a GitHub repository **variable** (`vars`), not Coolify;
configure that location even though the register groups both as repository
secrets. No setting or secret value is added by this acceptance branch.

Signed artifacts use detached Ed25519 signatures; Apple notarization and Windows
Authenticode are not claimed. The tag workflow retains artifacts and deploys
nothing. The independently built HTTPS installer/updater remains checksum-only;
use the signed-archive verification row before manually extracting signed files.

## Run the offline proofs

Prepare dependencies once on the worker (not on the founder's laptop):
`npm ci --prefix cli --ignore-scripts --no-audit --no-fund`. Warm the pinned
native dependency cache once, before the offline tests (no signing settings needed):

```sh
node --input-type=module - <<'JS'
import { PLATFORMS } from './cli/scripts/build-release.mjs';
import { readFileSync } from 'node:fs';
import { execFileSync } from 'node:child_process';
const lock = JSON.parse(readFileSync('cli/package-lock.json'));
for (const platform of Object.keys(PLATFORMS)) {
  const name = '@napi-rs/keyring-' + platform;
  const version = lock.packages['node_modules/' + name].version;
  execFileSync('npm', ['cache', 'add', name + '@' + version], { stdio: 'inherit' });
}
JS
```

Linux needs GNU tar,
gzip, OpenSSL, curl, wget and working Bubblewrap user namespaces, as in `cli.yml`.
The offline suite sets `npm_config_offline=true`, uses disposable loopback HTTP
servers, denies external Node fetches, and places scratch files under TMPDIR.
It generates ephemeral signing keys in memory, never release keys. The two plugin policy rows also run real Tank HTTP/SQL fixtures against a disposable loopback Postgres database named with `test`; set POOL_SCHEMA_DATABASE_URL for that service. No production SQL is permitted.

```sh
TMPDIR=/workspace/codex-cli-w3/.tmp PYTHONPATH=tank:tests python -m pytest -q tests/acceptance/test_cli.py --disable-socket --allow-unix-socket --allow-hosts=127.0.0.1,localhost,::1
```

A prerequisite failure is a failed proof, never a skipped row. Browser rows run
actual server actions, adapters and compiled TSX against fixture identities and
responses; the small JSX runtime fixture checks returned controls/text, not CSS
layout, real Trigger sign-in/Trigger sign-in browser acceptance or real keychain integration.
Native macOS/Windows acceptance still belongs on those operating systems. No
production acceptance is claimed by this offline sheet.
