# Tervor Code: coding-capable data and trainer adapter

Current main already contains M7/M14 data/gold, M8 evaluation, M3 explicit base
configuration and M9 capped jobs. M9 supported Zenas, Base and Tiger; its trainer
had no Opli task/context path and derived fit validation by input-hash sampling.
This change adds the missing `opli` path to that existing entrypoint and trainer.
It does not replace or republish #787/#792 grading or create a model family.

Run without credentials, network access, a database or model dependencies:

```sh
python3 -m tank.training_jobs.run --agent opli --dry-run --json
```

The JSON is a bounded offline preflight, **not launch readiness**. Exit 0 means the
existing CLI emitted the manifest successfully; read `status=blocked` and
`submitted=false`. `--dry-run --submit` remains invalid. The direct script form
works too. In the deployed flat `/app` layout, use
`python3 -m training_jobs.run --agent opli --dry-run --json`. The fixture corpus
is packaged under `training_jobs/fixtures`, copied by the existing image rules. Optional `--bundle path.json --model-version tervor-code-1.0 --day
2026-11-08` inspects a supplied sealed coding bundle. No HF client, fitting,
optimizer, upload or provider call is made on this path, regardless of ambient
HF credentials or base settings. The adapter intentionally does not treat an
ambient checkpoint as founder approval.

## Actual source capability

- M7 rows/snapshot hashes and M14 held-out gold are reused. An additive coding
  section binds explicit fit-validation rows, evaluation-only holdouts, source
  provenance, region and selection evidence with its own hash. M9's original
  training/gold hash and private artifact hash still apply.
- `train.coding_samples()` produces the prompt/completion conversation format
  consumed by existing `train.fit()`. `train.main()` supports `TRAIN_AGENT=opli`
  and uses those explicit train/validation partitions, with context cap 4096.
  It does not randomly resplit coding families. The cap is an adapter limit, not
  proof that an unselected checkpoint fits or supports that context.
- `--agent opli --submit` uses the existing job entrypoint, private artifact and
  registry identity, US-region restriction, configured hardware policy, quoted
  price, advisory submission lock, pending reservation and billing reconciliation.
  The coding adapter adds evidence checks and refuses a configured cap above the
  founder's $100 ceiling. That ceiling is not permission to launch a job here.
- The existing cross-product database held-out guard checks both training and fit
  validation inputs. The standalone trainer repeats the coding data/selection
  checks and the existing minimum-200-gold gate before calling `fit()`.
- Host preparation and trainer require matching explicit base ID/revision,
  licence/evidence, founder-approval reference, `a10g-small` hardware selection
  matching the existing execution policy, and hardware-fit evidence. Evidence
  references are trusted operator configuration for human review, not an
  automatic verification of founder authority or legal approval. No such
  selection is supplied or approved by this change.

The actual fit wiring is tested with a fake `fit()` and fake provider transport
through the real trainer entrypoint. That proves data flow and contract use; it
is not an optimizer step, a completed trained checkpoint or GPU-fit benchmark.
A test-only 200-case structural bundle is generated in tests, never presented as
independently reviewed production gold. No real upload or provider request ran.

## Data, separation and licences

The default corpus has one public training task from the existing pinned PyPA
sampleproject MIT fixture, plus one **separately sourced public fit-validation**
task from PyPA Flit. Its `normalize_file_permissions` completion is the exact
upstream function, at commit `eeaf9e783c87c331f1d73bb2f5553fc79016aae1`, under
BSD-3-Clause. The original source file, full copyright/licence notice, raw hashes
and pinned reference are retained under `tank/training_jobs/fixtures/tervor_code/public-validation/`.
The input deliberately mutates one implementation line; the completion is copied
from upstream source, not generated by a teacher/provider.

The original two synthetic validation fixtures are **evaluation only**, separate
from fit validation. The five synthetic gold cases remain held out. Neither set
enters fitting. Synthetic/provider/private tenant rows are rejected from training
and fit validation; declared private holdout provenance is also refused. Sources,
licence evidence, row input/output hashes, stable source families and individual
source/input/answer file content are bound and checked across all four partitions.
A recomputed outer hash cannot conceal a mismatched source, copied held-out
input, relabelled family, unsupported source kind, private tenant or extra private
row metadata. These are structural/provenance guards, not automatic proof that
an arbitrary operator's asserted web licence or approval reference is genuine.
Human source review remains required for added corpora.

Coding bundles are capped at 8 MiB, provenance at 1,000 records and individual
row/source records at 64 KiB. All shared training/gold guards remain in place.
No raw tenant traffic, correction store, teacher generation or private client
corpus is collected by this adapter. It is a small reproducible readiness corpus,
not an adequately sized production fine-tuning dataset.

## Exact current manifest and remaining gates

[Sanitized preflight manifest](evidence/tervor-code-training-preflight-2026-11-08.json)
records 1 training, 1 fit-validation, 5 gold and 2 evaluation-only rows, plus exact
partition/sample/bundle hashes. Every selection value is null and marked
`missing`: base model ID, immutable revision, licence, licence evidence,
founder-approval reference, hardware selection and hardware-fit evidence.
`MODEL.md` specifies only “a Qwen coder base”; this adapter does not choose one.
Cost stays null because approved checkpoint, measured hardware fit, quote and
runtime are not established. Provider requests/paid jobs are zero.

Missing production gates include 195 more cases merely to reach the structural
200-gold minimum; independent review, sufficient training/validation data,
calibrated Tank/DeepEval, shadow evaluation and launch approval are additional
requirements. The bounded-expression verifier remains available unchanged and
scope-limited; arbitrary-Python grading remains fail-closed. Validation loss is
not a gold/model-quality pass. Trained artifacts remain `tervor_gold_pending`,
with `eligible=false`; this adapter never promotes or changes serving.

No runtime Compose, production setting, service activation, paid/provider/GPU job,
HF upload, new checkpoint selection, merge or deployment belongs to this PR.
