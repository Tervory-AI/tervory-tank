# RIG-3 retailer feeds

`/rig/admin` is available to the active tenant's Clerk organization administrator or a listed founder. Every operation resolves that identity server-side, goes through Tank, and uses a separate Tank-to-Rig retailer credential. The browser never receives a room key, stored supplier credentials, source amounts, saved price rules or exchange rates.

## Import and refresh

Use `/v1/access/rig/admin/import`, `/connect` and `/refresh` through the authenticated retailer admin. These call ACCESS-1's existing feed parsing, connection vault, refresh and receipt functions. The general `/v1/access/feeds/*` routes retain Tiger authorization before body parsing and refuse a Rig target; the general Workspace Access proxy also rejects `target`. The source choices retain Shopify, WooCommerce, Google Merchant, Zanders, Sports South, RSR and Jerry's, and add **Any catalogue**. CSV/TSV, Excel `.xlsx`, XML and JSON all use the same `rigbox.feeds.pull` parser interface. The original ACCESS distributor price adapters remain available for Tiger; Rig's catalogue parsers also recognize their field names. Inventory-only EDI still serves Tiger; catalogue creation needs product labels and images.

Each feed has a name, website, currency, two-letter country code and price type (**supplier cost** or **selling price**). Different feeds on the same website remain separate. Press **Suggest field mapping**, review the dropdowns and confirm. Only column names are returned by the preview, never source values. A nested JSON list or XML record path can be supplied, for example `catalogue.products`. The confirmed mapping and declarations are saved in `tank.rig_feed_settings`; scheduled connections retain them in their encrypted configuration too. **Use saved mapping** prepares the form for a later upload. An unconfirmed import may reuse its existing saved map, but a new feed requires confirmation. All web operations remain behind the dedicated retailer route.

Files are limited to 8 MB and 50,000 products, with a 12 MB request envelope to accommodate base64 Excel uploads. XML rejects NUL, DOCTYPE and ENTITY declarations before parsing. Excel reads the first worksheet as data, supports inline/shared strings, and refuses formulas, external worksheet relationships and oversized ZIP contents (32 MB expanded total, 8 MB per part, 1,000 entries). No spreadsheet engine or external dependency runs. Product fields may be nested up to 12 levels; ambiguous headings require an explicit choice.

Connections use the existing ACCESS vault and same-site, pinned HTTPS fetcher. Public, bearer, Shopify header and HTTP Basic/WooCommerce credentials are supported. Credentials are entered only in the authenticated connection form and stored encrypted. Configure a read-only export URL or the first Shopify/WooCommerce REST page, without a query or embedded credentials. Pagination follows Shopify's next-page link or WooCommerce's total-page count, stays on the same host and path, and accepts only pagination query fields. All pages are collected before import, with a combined 8 MB / 100-page limit. Other sources supply complete files. File imports need no vault or supplier credentials.

ACCESS owns the refresh schedule: 03:00 UTC, plus **Refresh now**. Its `rig_feed_loop` runs in Tank's existing ACCESS lifespan because Tank alone owns the encrypted feed credentials, pinned supplier fetcher and durable schedule rows. Rig never receives those credentials. The loop starts and stops with ACCESS, claims only due `rig:` rows with `FOR UPDATE SKIP LOCKED`, and leaves Tiger's refresh behavior unchanged. The connection name is `rig:<provider>:<feed-name>` (legacy unnamed feeds keep `rig:<provider>`); the `rig:` prefix keeps Tiger's existing connections separate. A failed fetch is recorded as `feed_refresh_failed` for nightly runs. It does not replace catalogue data. A completed file produces `{added, updated, rejected}` in `agent_rig.feed_receipts`, mirrored in `tank.access_feed_batches.rig_summary` and the existing ACCESS receipt stream. Rig stores the import and its receipt in the same transaction. If Tank loses its connection after a commit, check import history before retrying; the UI does not claim that the import was rolled back.

All rows, families, fit references and template defaults are validated before the transaction commits. A bad row rejects the whole file. Re-importing a valid file updates its SKUs. Feed-supplied fits enter the review queue as `source='suggested'`, with evidence, and remain invisible until approved. Refreshes and later suggestions preserve human approvals/rejections. When a feed supplies no fits, the existing `rig.fit_suggest` route is used; unavailability is reported separately from a successful import. No new paid provider or route is added.

## Private prices

The retailer sets a shop currency (ZAR by default) and a default private rule. Freight is per item in the feed's currency; duty and gross margin are percentages. A complete supplier/feed override takes precedence over a country override, then its region and the default. EU includes its 27 member country codes; US and NZ use their country codes. Other countries can have their own two-letter rule. Saved rule values never return to the browser.

The founder sets a direct rate for each source/target currency pair. Same-currency conversion is always 1; a missing foreign rate rejects the import. Cost feeds use decimal arithmetic and round once to cents:

`((supplier cost + freight) × (1 + duty / 100) × FX rate) / (1 - gross margin / 100)`

Selling-price feeds skip every landed-cost input and preserve the given amount in the same currency. Foreign selling prices receive currency conversion only, rounded once to cents. This makes the store's price choice independent of later margin, freight and duty changes.

Source amounts, country, price type and feed identity live in the private `agent_rig.supplier_costs` table. Only the resulting indicative shop price reaches public products. Rule, shop-currency and FX changes reprice all imported products atomically using their stored provenance. An invalid rule/rate leaves both configuration and products unchanged. Same-currency selling-price imports need no cost rule.

Tiger can call `POST /v1/access/rig/tiger` with its own existing key and the tenant, SKU, price, currency and/or availability. Tank forwards that narrow update to Rig. A product belonging to a feed is refused; fitment is never updated by this path.

## Configuration and deployment

Configure a new, distinct `RIG_RETAILER_KEY` in Coolify on **Tank and agent-rig only**. The empty name is declared in `.env.example`; no value is committed. Do not give it to rig-brain, a browser gateway, Hermes or Workspace. Tank calls `http://agent-rig:8003/internal/retailer/*` with this key and derives tenant/founder status from its own authenticated actor. The private listener shares the catalogue service and application lifespan. Traefik routes only port 8000, where retailer control paths do not exist; port 8003 is never published on the host. With the key absent, the listener stays off and Tank refuses retailer operations. Reuse `TANK_VAULT_KEY` on Tank and `TERVORY_ADMIN_USER_IDS` on Tank/Workspace. Sample file imports need no live supplier credentials.

Deploy Tank, agent-rig and Workspace after review. Both schemas are additive and idempotent. This lane changes no room networks, quote flow, widget bundle or 3D code. The compose additions pass the dedicated retailer key to its two owners only. Live Custom Nation shopper data still belongs on the future ZA host; the following checks use synthetic office products only.

## Prove it after deploy

1. Check that a POST to `https://rig.tervory.com/internal/retailer/panel` returns 404, including with the existing room key. From Tank's corridor, the private port must reject the room key and accept only `RIG_RETAILER_KEY`; never place either value in commands, logs or URLs. Sign in as the sample tenant's organization admin and open `/rig/admin`. Set freight 1, duty 10%, gross margin 20%, shop currency ZAR. As founder set USD→ZAR 18.50, EUR→ZAR 20 and NZD→ZAR 11.
2. Import all five files listed in `catalogues/samples/README.md`, declaring the specified currency, country and price type, and confirming each suggested mapping. Their expected ZAR prices are 534.19, 440.00, 196.63, 788.56 and 799.95. Every receipt should show one added product and zero rejected. Re-import using the saved mapping and check one updated product. The original Shopify, WooCommerce, Google and distributor samples remain available; Shopify supplies the shade fit for the next check.
3. Check the sample shade in the fit queue. Before approval it must be absent from the shopper's approved combinations. Approve it, verify it appears, then refresh/re-import and confirm the decision remains intact. Reject it and confirm it is removed.
4. Inspect the browser's product/admin responses: one indicative price only; no stored cost, freight, duty, margin, FX or credential values. Change an EU rule and verify only the EU cost product changes; add a feed-specific rule and verify it takes precedence. The store selling price must remain 799.95.
5. Connect a controlled read-only sample endpoint, press **Refresh now**, and verify `tank.access_feed_connections.rig_refresh_at`. After the scheduled run check the tenant's `tank.access_receipts` and `agent_rig.feed_receipts` rows. An unavailable supplier must leave the prior catalogue intact.
6. Search for an absent sample product; check the admin's unmatched searches. A second tenant must see none of the first tenant's products, review queue, templates, connections or receipts.

They cover the sample providers, all four distributor adapters, tenant boundaries, private pricing, review visibility, refreshes, real PostgreSQL rollback and schema reapplication. `tests/rig_feeds_admin_browser.mjs` exercises the production component against synthetic responses and writes the 375px/1440px screenshots to a temporary directory (`RIG_SCREENSHOT_DIR` can override it).
